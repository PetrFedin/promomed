## Institutional Pilot Proposal Studio v1

Purpose:

turn the now-live readiness / onboarding / diligence stack into a commercial first-meeting tool without crossing the real-party authority gate.

Flow:

`partner archetype -> value hypothesis -> use-case options -> pilot scope modules -> customer inputs -> stakeholders -> success formulas -> procurement prerequisites -> commercial boundary -> deterministic proposal export`.

Hard boundaries:

- proposal works from archetype, not a synthetic named customer;
- no real customer is claimed;
- no real pilot is claimed;
- no target is claimed agreed;
- no timeline is claimed agreed;
- no price is claimed agreed;
- no PO or revenue is claimed;
- no contract is created;
- no new table/migration/approval authority is created;
- External Participation Acceptance remains `GATED`.

Supported archetypes:

- clinic;
- university;
- medical society;
- pharma;
- knowledge provider;
- strategic partner.

Commercial consequence:

Promomed can tailor the first institutional conversation to the buyer type and expose exactly what the buyer must provide before pilot/procurement, without fabricating traction.

## Next dependency after green merge/live proof

Use the Proposal Studio in prospecting / real external conversations.

The next implementation must remain non-authoritative unless a real non-demo party supplies evidence that justifies canonical receipt/review/acceptance semantics.

A safe follow-on layer, if no external party is yet available, is a **Proposal Comparison / Buyer Fit Matrix** across archetypes and scope options—again as planning, not customer truth.
